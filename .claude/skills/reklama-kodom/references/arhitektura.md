## Почему 2.5D, а не настоящий 3D

Полноценный растеризатор с z-буфером не нужен. Почти всё, что встречается в рекламном ролике, — плоскости: экран телефона, карточка товара, грань коробки, стена, пол. Плоскость проецируется четырьмя углами и натягивается перспективным преобразованием. Это точно, быстро и управляется покадрово.

Объём добирается светом (`svet.md`), а не числом полигонов.

## Камера

```python
cam = Camera(w, h, fov)
cam.set(pos, target, roll)
sp, z = cam.project(points3d)     # (N,2) экран, (N,) глубина
```

Внутри — `lookAt` и перспективное деление. Ориентация базиса: `right = cross(up, forward)`, `up2 = cross(forward, right)`. Знак здесь перепутать легче всего, последствия — в `bagi.md` №1.

Дополнительно: `focus` и `dof` для глубины резкости, `shift` для тряски, `zoom`.

## Квады

```python
warp_quad(dst, tex_rgba, corners, opacity=1.0, blur=0.0)
```

Углы в порядке **TL, TR, BR, BL** — один порядок на весь проект, иначе текстуры будут переворачиваться. Внутри: ограничивающий прямоугольник, перспективное преобразование только в него, предумноженная альфа (иначе по краям тёмная кайма), композитинг.

Сортировка по глубине — алгоритмом художника: считаешь среднюю глубину квада и рисуешь от дальнего к ближнему.

Обратное отображение — точка текстуры в мир — билинейно по квадy:
```python
p = quad_uv(corners3d, u, v)      # u,v в 0…1
```
Этим линия ложится ровно на экран телефона или на грань коробки.

## Tex — поверхность для рисования

Обёртка над Pillow с суперсэмплингом: рисуешь в координатах результата, внутри всё происходит в 2–3 раза крупнее и ужимается в конце. Даёт сглаживание там, где Pillow его не делает.

```python
t = Tex(w, h, ss=2, bg=(14, 12, 18))
t.rr((x0, y0, x1, y1), r, fill=...)       # скруглённый прямоугольник
t.text((x, y), s, font, size, color, anchor="lm", tracking=0)
a = t.np()                                 # float32 RGBA 0…1
```

`tracking` — межбуквенный интервал, которого в Pillow нет: при ненулевом значении символы рисуются по одному.

## Кеш текстур

Текстуры строятся по параметрам и кешируются по ним:

```python
cached(("screen", res, nchars, nrows), build)
```

Это то, что делает моушн-блюр доступным: подкадры отличаются геометрией, а содержимое экрана то же самое, и ключ кеша совпадает. Квантуй непрерывные параметры (`round(fill, 3)`), иначе кеш не попадает ни разу.

## Линия — носитель идеи

```python
Path(points2d)                 # перепараметризация по длине дуги
Path.from3d(cam, points3d)
Path.bezier(p0, p1, p2, p3)
path.sub(u0, u1)               # участок по доле длины
```

`draw_line` строит маску штриха с переменной толщиной и яркостью, затем:
- при `cool < 1` — аддитивное свечение несколькими сигмами плюс раскалённое ядро
- при `cool > 0` — композитинг краски по альфе

Один вызов, параметр `cool` ведёт от света к печати. Поэтому «линия становится краской» — не переход между двумя эффектами, а одно состояние, меняющееся во времени.

## Пост-цепочка

Порядок и смысл — в `svet.md`. Технически: блум считается на 1/4 разрешения (на глаз не отличить, вчетверо быстрее), хроматическая аберрация — через заранее посчитанные карты `remap`, зерно — из нескольких заготовленных полей, которые циклически меняются (новый шум каждый кадр дороже и не лучше).

## Выдача кадров

Кадры пишутся PNG с быстрым сжатием, потом собираются ffmpeg. Это медленнее прямой трубы, но даёт то, ради чего всё: **можно перерендерить любой интервал, не трогая остальное.**

```bash
python3 render.py --fmt 16x9 --scale 1.0 --jobs 4
python3 render.py --fmt 16x9 --start 9.98 --end 10.12   # только стык
python3 render.py --fmt 16x9 --scale 0.6 --stills 2.4,5.9,12.6
```

Параллелится процессами: `cv2.setNumThreads(1)` и пул по числу ядер. Четыре ядра дают около 200 с на 1272 кадра в 1080p.

Сборка:
```bash
ffmpeg -framerate 60 -i frames/%05d.png -i score.wav \
  -c:v libx264 -crf 19 -preset slow -tune film -pix_fmt yuv420p \
  -color_primaries bt709 -color_trc bt709 -colorspace bt709 \
  -movflags +faststart -c:a aac -b:a 256k -shortest out.mp4
```
`-tune film` важен: без него зерно съедает битрейт.

## Звук

Музыка и эффекты синтезируются numpy. Библиотека не нужна: щелчок — отфильтрованный шум с резким спадом, удар — синус с падающей частотой, свист — полосовой шум с огибающей-колоколом, реверберация — свёртка через БПФ с затухающим шумом.

Главное — не тембры, а **сетка**: эффекты стоят на тех же тактовых линиях, что и картинка. Зашей проверку в код:

```python
assert not [c for c in cues if abs(c - HERO_HIT) < 0.060 and c != HERO_HIT], \
    "в окне ±60 мс от геройского удара не должно быть ничего, кроме него"
```

Мастер: нормализация по RMS, затем мягкий ограничитель **только выше порога** — иначе это не ограничитель, а нормализатор, и он съест всю динамику.
