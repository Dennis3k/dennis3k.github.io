# Motion blur и камера

## Почему смаз нельзя подделать

Движение, снятое без смаза, стробит: на 30 fps быстрый объект прыгает рывками. Смаз, нарисованный «полосками» вручную, выдаёт себя на стыке с резким кадром. Настоящий смаз — усреднение нескольких положений внутри одного кадра, и он получается сам, если кадр — функция времени.

```
кадр(t) = среднее от draw(t + (i + 0.5)/N · dt · shutter), i = 0..N−1
```

## Почему усреднять надо деревом

Очевидный способ — рисовать N субкадров с прозрачностью 1/N в один буфер. На 8-битной канве это ломается: при N = 32 вклад тёмного пикселя (значение 10) равен 0.31 уровня, округляется в ноль и не накапливается никогда. Тени уходят в чёрный, фон пропадает ровно там, где смаз сильнее всего.

Рабочий способ — попарное усреднение бинарным деревом. Каждый шаг — честные 50/50 двух канв, ошибка округления ±0.5 уровня на шаг, за 5 шагов (N = 32) — пара уровней суммарно, не видно.

Реализация — `scripts/render.js`, класс `Renderer`. N округляй до степени двойки, иначе дерево не сойдётся.

## Сколько субкадров

Расписание держи в карте тайминга рядом со склейками — это часть монтажа, а не настройка рендера:

```js
export function blurAt(t) {
  const fast = [[0.05, 0.40, 28], [1.55, 1.95, 32], [4.80, 5.55, 32], ...];
  for (const [a, b, n] of fast) if (t >= a && t < b) return n;
  return 4;                      // немного смаза есть всегда
}
```

Ориентиры: пролёты мимо камеры и слэмы — 32; проезды и подъёмы — 8–16; удержание — 4. Ноль не ставь нигде: кадр совсем без смаза среди смазанных выглядит выпавшим.

## Шторка

`shutter = 0.85` от длительности кадра. Выборка идёт вперёд от `t`, то есть кадр, начинающийся ровно на таймкоде удара, захватывает уже послеударное состояние и получается резким, а предыдущий — смазанным на подлёте. Это именно то, что нужно: слово читается на своём кадре.

Шторка 1.0 даёт более «жирный» смаз, но съедает резкость удара. Меньше 0.5 — начинает стробить.

## Камера: масштаб вокруг точки ≠ кадрирование этой точки

Самая дорогая ошибка в моушне. Вот такой «камера»:

```js
ctx.translate(cx, cy); ctx.scale(s, s); ctx.translate(-cx, -cy);
```

удерживает точку `(cx, cy)` на месте и увеличивает всё вокруг неё. Если `cx` — левое слово длинной строки, оно так и останется у левого края, просто станет больше, и при зуме 2× уедет за кадр целиком.

Чтобы точка оказалась **в центре кадра**, нужен ещё перенос:

```js
function cam(ctx, cx, cy, s, dx = 0, dy = 0) {
  ctx.translate(cx + dx, cy + dy); ctx.scale(s, s); ctx.translate(-cx, -cy);
}
cam(ctx, wordX, lineY, zoom, W / 2 - wordX, 0);   // слово — в центре
```

Проверяется одним стиллом на таймкоде зума. Если объект не по центру — формула не та.

## Движения камеры

Сплайн без рывков скорости — `easeInOutQuint`. Линейные проезды выдают себя мгновенно.

**Камера не должна следовать за дискретным событием.** Если она привязана к каретке, которая прыгает по символам, то на каждом символе получает скачок — и под шторкой смазывается весь кадр, текст перестаёт читаться. Привязывай камеру к непрерывной величине:

```js
const p = clamp(inv(typeStart, typeEnd, t));          // 0..1, непрерывно
const camX = W / 2 + W * 0.055 * Math.cos(p * Math.PI);
```

Каретка при этом прыгает — ей можно.

## Тряска

Затухающая синусоида от момента удара, по каждому удару своя, суммируются:

```js
const decay = (t, f = 9, tau = 0.17) => (t <= 0 ? 0 : Math.exp(-t / tau) * Math.sin(TAU * f * t));
```

Тряси фон, завёрнутый в оверскан ×1.05–1.07, и отдельно — текст, с амплитудой примерно 0.7 от фоновой и **без** оверскана. Если завернуть текст тоже, он вылезет за кадр: оверскан увеличивает всё, включая полноширинную строку.
