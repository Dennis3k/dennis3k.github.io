# Конвейер: от функции кадра до мастера

## Страница

Один `<canvas>` нужного размера и глобальные входы для захвата. Размер задаётся атрибутами канвы, а не CSS: мы читаем пиксели канвы напрямую, поэтому devicePixelRatio и размер окна ни на что не влияют.

```html
<canvas id="c"></canvas>
<script type="module">
import { Renderer, FPS, TOTAL } from './src/main.js';
const q = new URLSearchParams(location.search);
const W = +(q.get('w') || 1920), H = +(q.get('h') || 1080);
const cv = document.getElementById('c'); cv.width = W; cv.height = H;
const ctx = cv.getContext('2d', { alpha: false });
const R = new Renderer(W, H);
window.__total = TOTAL; window.__fps = FPS;
window.__frame = (f) => { R.frame(ctx, f / FPS, {}); return cv.toDataURL('image/png'); };
window.__at = (t, sub) => { R.frame(ctx, t, { sub }); return cv.toDataURL('image/png'); };
await document.fonts.ready;     // иначе первые кадры намеряют не тот шрифт
window.__ready = true;
</script>
```

`await document.fonts.ready` обязателен: без него первые кадры измеряют текст системным шрифтом, и вёрстка в них разъезжается.

## Захват

`scripts/capture.mjs` гоняет страницу кадр за кадром и пишет PNG прямо в stdin ffmpeg — ничего не ложится на диск и ни один кадр не теряется (в отличие от экранной записи).

```bash
node tools/capture.mjs h      # 1920×1080 → out/*_16x9.mp4
node tools/capture.mjs v      # 1080×1920 → out/*_9x16.mp4
```

PNG, а не JPEG: тёмные градиенты и звёздное небо на JPEG дают блочность, которую потом добивает x264. Разница по времени — около минуты на ролик, оно того стоит.

Кодек:

```
-c:v libx264 -preset medium -crf 15 -pix_fmt yuv420p
-colorspace bt709 -color_primaries bt709 -color_trc bt709 -movflags +faststart
```

`yuv420p` и `+faststart` нужны, чтобы файл игрался везде, включая браузеры и соцсети.

## Стиллы

```bash
node tools/shot.mjs h 1.75 3.78 16.60   # горизонт
node tools/shot.mjs v 24.90             # вертикаль
```

Для стиллов ставь 1–2 субкадра: смотреть композицию удобнее по резкому кадру, а смаз проверяется на контактном листе.

PNG 1920×1080 весят много. Перед просмотром ужимай до ~560 px по ширине — этого хватает, чтобы увидеть всё, кроме микротипографики, а контекста экономит прилично.

## Бюджет времени

Считается заранее, по расписанию motion blur:

```
субкадров всего = Σ по кадрам blurAt(t)
```

Ориентир: 780 кадров, в среднем 12.8 субкадра → ~10 000 отрисовок → ~15 минут на формат в 1080p на 4 ядрах. Два формата параллельно укладываются в те же 15 минут, по ядру на Chromium.

Запускай рендер фоном (`setsid node tools/capture.mjs h > out/render_h.log 2>&1 &`) и жди по логу (`until grep -q "done ->" ...`). Пока рендерится — пишется звук, README или текст поста.

## Пересборка после правки

Правка в одном файле → полный пересчёт обоих форматов. Это норма конвейера, а не повод патчить отдельные кадры. Единственное, что стоит делать перед полным рендером, — проверить правку на двух-трёх стиллах.

Если правка касалась только одного формата, второй всё равно перерендерь: иначе два мастера собраны из разных версий кода, и через неделю никто не вспомнит, из каких.

## Окружение

- Chromium из Playwright: `PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers`, свой скачивать не надо.
- Флаги запуска: `--force-color-profile=srgb --font-render-hinting=none` — иначе цвет и шрифт поедут между машинами.
- Шрифты: canvas берёт системные по имени семейства. Проверить, что вес реально работает, можно сравнив ширину строки на весах 400 и 900 — если совпали, вес не подхватился.
